# 點名模組

四種角色共用「出缺席」入口，位於「教務與學習」功能群組。

| 角色 | 查閱範圍 | 登錄／更正 |
| --- | --- | --- |
| 學生 | 自己的紀錄，含退選後的歷史紀錄 | 不可 |
| 老師 | 自己授課課程的紀錄 | 僅自己的授課課程 |
| 行政、管理員 | 全校紀錄，可依課程與日期篩選 | 不可 |

## 操作

1. 老師進入「課程查詢」，在自己的授課課程旁按「開啟點名」。也可從「出缺席」篩選課程後開啟。
2. 在彈出視窗選擇本堂課的日期與節次，按「開始點名」，顯示該課程全班已選課學生名單。
3. 設定本堂課為「點名中」或「關閉」，並自行填寫「備註／缺席人數」。下方可逐一選擇出席、缺席、遲到或請假；請假須已有涵蓋該日期且經老師核准的申請。
4. 按「儲存本堂點名」一次儲存整班，成功後進入該課程與日期的出缺席紀錄。
5. 主列表每堂課一列，依序為「日期節次、課程、學生人數、狀態、備註／缺席人數（老師填寫）、修改」。按「修改」開啟整堂課視窗；再次開啟會保留既有狀態與備註。關閉視窗不會儲存尚未送出的變更。
6. 學生及行政、管理員使用「查看」讀取明細，沒有寫入操作；學生只能看自己的個人出缺席結果。

開啟點名即建立「點名中」的課堂紀錄；整班儲存可保留「未點名」，不會自動視為缺席。既有學生結果改為未點名並儲存會清除該筆結果。若有任一筆不合法，整批不會寫入；若選課名單已變動，會要求重新開啟點名。點名按鈕只出現在老師自己的課程，API 也驗證授課權限。

尚未點名不等同缺席。每一筆為一個節次，不以全校課表作為點名清單；不同課程與節次各自保存。日期可用於補登或補課，不限制為課程原定星期。

## 模組結構

- `school/attendance.py`：查詢、課程選單、已選課名單、驗證、寫入與路由註冊。
- `school/extensions.py`：呼叫 `attendance.register(router)`，沿用原有登入與權限機制。
- `static/attendance.js`：獨立封裝查詢、篩選與登錄視窗；透過 `configure()` 接收入口提供的 API、表格、表单與視窗工具。
- `school/database.py`：建立個人明細 `attendance` 與課堂摘要 `attendance_classes`。既有明細依課程、日期、節次轉為「關閉」的課堂摘要；保留個人明細與其他既有資料。
- `tests/test_attendance.py`：單元與 HTTP 系統測試；瀏覽器流程在 `tests/test_e2e.py`。

## API

| 方法與路徑 | 功能 |
| --- | --- |
| `GET /api/attendance/classes` | 課堂主列表，可依課程及日期篩選，依角色限制範圍 |
| `POST /api/attendance/classes` | 授課老師開啟課堂；若已存在則帶入原狀態及備註 |
| `GET /api/attendance?course_id=2&date=2026-10-07` | 依角色範圍查詢，兩個篩選參數皆可省略 |
| `GET /api/attendance/courses` | 有權限的課程選單 |
| `GET /api/attendance/courses/2/students` | 該課程有效的已選課學生，僅授課老師 |
| `POST /api/attendance` | 新增或更正，僅授課老師 |
| `POST /api/attendance/roll-call` | 一次儲存整堂課的全班點名，僅授課老師，交易內整批成功或取消 |

寫入範例（學生編號需來自課程名單）：

```json
{"course_id":2,"student_id":4,"attendance_date":"2026-10-07","period":3,"status":"present","note":""}
```

可用狀態為 `present`、`absent`、`late`、`excused`。節次須在課程範圍內，備註最多 500 字；新紀錄只接受該課程的有效已選課學生，既有紀錄可於退選後更正。每次寫入保存登錄人與更新時間，並新增操作紀錄。

整堂點名請求包含 `course_id`、`attendance_date`、`period`、`class_status`（`open`／`closed`）、`class_note`（老師自行填寫，最多 500 字）與 `students` 陣列；每位學生包含 `student_id`、`status`、`note`。空白學生狀態代表未點名。學生不可重複，且須與目前有效選課名單完全相符。同一堂課重複儲存會更新原紀錄；學生人數取儲存時有效選課名單人數。

具有出缺席紀錄的課程不能刪除，相关學生或登錄人不能直接變更角色，避免歷史資料失去對應。
